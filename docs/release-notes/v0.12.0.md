# v0.12.0 — the audio language in the player's More menu, the wheel scrolls the page again, and availability in My list

This release fixes the v0.11.0 problem where the default player gave no visible way to change the audio language, puts the Magic Remote wheel back on the page, and shows on My list which titles your own Plex servers have. None of it has been run on a television yet, so read Known issues before installing.

## Changed from v0.11.0: the Magic Remote wheel scrolls the page again

v0.11.0 made the wheel scroll the row under the pointer sideways. This release takes that back: the wheel always scrolls the page up and down, wherever the pointer rests, as it did before v0.11.0. A row still moves sideways with Left and Right, and when the pointer rests at the left or right edge of a row.

## What's new

- **My list shows whether your servers have each title.** A mark in the poster's corner says whether a library on one of your own Plex Media Servers holds the title (never a streaming service): a ring with a play triangle when it is available, a ring with a bar when every server answered and none has it, and a ring with a question mark when it is still to check, for example because a server did not answer or the lookup failed. A failed lookup never shows as not available. A title is matched by its Plex identifier only. Sort & Filter has an **Available only** filter (it was called "On your servers") and an **Availability** sort: available first, then the ones still to check, then the ones no server has. The default order is still Date added, newest first.
- **More space between sections** on Home, Library, Detail, Search and person pages: 96 pixels between rows on a 1080p television, 64 on a 720p one.
- **An ivory Play button in the MultiPlex player HUD.** The large play/pause disc is now ivory with a dark symbol, and its glow when selected stays between the buttons next to it instead of spreading over them.

## Fixed

- **The audio language could not be changed from the default player HUD.** In v0.11.0 the MultiPlex HUD's More menu had one "Audio and subtitles" row, which opened on the subtitles list; the audio list was only reachable by pressing Left from there, and nothing on screen said so. More now lists **Audio**, whenever the video has two or more audio tracks, and **Subtitles**, each opening its own list.

## Compatibility

- **Plays video, verified by watching it — no television for this package.** Nothing in this release was installed or run on a television by the people who made it. The playback code is PlxNative's, which its maintainer runs on a 2019 LG 49SM9000PLA (platform release 4.10.2, marketed as webOS 4.5), but that is evidence about PlxNative's packages, not this one.
- **Plays video, reported by someone else — no reports for this package.** PlxNative 0.10.0 has [reports from its own users](https://github.com/GLinnik21/plx-native/releases/tag/v0.10.0); they are about a different package and do not carry over to MultiPlex.
- **Starts, and nothing further is known — firmware from webOS 4.0 up.** The release run checks this binary's libraries and symbols against the firmware images webosbrew has from webOS 4.0 up, and the verdict for this exact package is in the [technical audit](https://github.com/Shibeon/MultiPlex-LGTV/blob/main/docs/release-audits/v0.12.0.md). That grades startup and says nothing about whether video plays.

## Known issues

- **Every change in this release is unseen on a television:** the Audio row in the player's More menu, the wheel, the new spacing, the availability marks in My list and the ivory Play button. They were checked with automated tests and on a desktop simulator only. The availability marks have only been run against the project's test server, not a real Plex Media Server.
- **The known issues of v0.11.0 still apply.** Its other features, among them the audio modes' in-app decoding, have still not been run on a television; running MultiPlex and PlxNative side by side has still not been tried on one; and PlxNative 0.10.0's known issues are inherited. The list is in [the v0.11.0 release note](https://github.com/Shibeon/MultiPlex-LGTV/releases/tag/v0.11.0).

## Installing

Download **app.multiplex.native_0.12.0_arm.ipk** and install it with the [Homebrew Channel](https://github.com/webosbrew/webos-homebrew-channel) or [dev-manager-desktop](https://github.com/webosbrew/dev-manager-desktop). You do **not** need a rooted TV. MultiPlex is not listed in the Homebrew Channel's catalogue, so download the file from this page.

Nothing in this distribution chain is signed, so this sha256 is what tells you the file you have is the file published here:

```
__IPK_SHA256__  app.multiplex.native_0.12.0_arm.ipk
```

[Installing and checking a download](https://github.com/Shibeon/MultiPlex-LGTV/blob/main/docs/install-and-verify.md) covers the other assets, how to check the hash on each platform, and the Developer Mode expiry that uninstalls your apps. MultiPlex is licensed GPL-3.0-or-later, like PlxNative, and bundles FFmpeg under LGPL-2.1-or-later and the libass subtitle renderer with its own libraries under their licences; the complete corresponding source is attached to this release. Exactly what was built, verified and shipped is in the [technical audit for v0.12.0](https://github.com/Shibeon/MultiPlex-LGTV/blob/main/docs/release-audits/v0.12.0.md).
