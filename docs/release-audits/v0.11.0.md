# Release audit — v0.11.0

The evidence behind [the v0.11.0 release note](https://github.com/Shibeon/MultiPlex-LGTV/blob/main/docs/release-notes/v0.11.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written by a person before the release ran.

**The first release of MultiPlex, a fork of [PlxNative](https://github.com/GLinnik21/plx-native).** The fork took PlxNative's `main` after its v0.10.0 release audit (`31e6f24b`), up to and including `8e0f66a6` (2026-11-13), plus one Dependabot bump; every later commit is the fork's own (the identity change `21cbaf03` onward). The authored half below was written on 2026-11-15 against the fork's `main` at `e17da430`, by a drafting agent with no television, no Plex account and no package build: it records what the repository and CI say, and nothing in it was measured on a device. The v0.10.0 tag is not in the fork's repository, and no earlier MultiPlex release exists, so the GitHub compare range appended to the release body has no previous tag to start from.

The tiers that ran are structurally blind to most of what this release changed: frame rate and text rasterization on LG's renderer, the audio modes' decode timing against the video plane, the Magic Remote wheel's feel, and webOS DB8 behaviour with two related installs. ## Known issues at release, with provenance

- **New features unseen on a television** (the wheel on rows, section spacing, the audio modes' in-app decoding, the search person card against a real server): each commit's body (`d91e5e50`, `3ffccd12`, `058f33be`, `7dbb8196`) records host tests, simulator replays and the mock server only. The audio-mode decoding's lip sync, processor load and the fallback to compressed sound were not measured anywhere.
- **Side-by-side with PlxNative, separated in code and never run on a set.**
  - The app ids differ (`app.multiplex.native` against `com.beb.plxnative`, from `ci/install-identities.json` here and at `31e6f24b`), and the storage helper's DB8 kind is named after its own service.
  - The stable and nightly installs' DB8 object ids were `plxstate.stable` and `plxstate.night`, the same as PlxNative's stable and nightly installs', and DB8 ids are global across kinds. This release moves them to `mpxstate.stable` and `mpxstate.night`; the debug id is unchanged. At each helper start, `Backend::adopt_legacy_record` gets the old id once. Only when the object there is of MultiPlex's own kind does it copy it to the new id (a create that cannot overwrite, and only while the new id is empty), read the new id back, re-read the old object, check its kind again and purge it (`del` with `purge: true`, so no plaintext token outlives a sign-out or Delete all local data under the old id). An object of another kind, or a read DB8 refuses with -3999 or -3963, is never kept, written or deleted. A transport error or any other refusal is retried on the next connection. This is pinned by `our_own_legacy_record_moves_to_the_new_id_and_the_old_one_is_purged`, `an_own_legacy_record_left_beside_a_current_one_is_purged_without_touching_the_current_one`, `plxnatives_record_is_never_adopted_written_or_deleted` and `a_transient_failure_retries_adoption_on_the_next_connection_instead_of_abandoning_it`, all against a mock DB8; the `del` call's shape and error codes come from the webOS OSE DB8 API reference, not from a set.
  - Boot and Delete all local data no longer remove any `/tmp/plxnative-*` file. `remove_legacy_runtime_files` from `0f7446f2` is deleted, and `preparing_the_runtime_root_leaves_plxnative_files_alone` (observed failing before the fix) and `delete_all_local_data_leaves_plxnative_files_alone` pin the new behaviour.
  - What a set has to settle is `docs/two-installs.md` §6 item 8.
- **PlxNative 0.10.0's known issues** are inherited unchanged; their provenance is in PlxNative's v0.10.0 audit.

## Deliberately not done

- **No submission to the webosbrew catalogue** and no change to `webosbrew/apps-repo`: the release is published on GitHub only, by the owner's decision. The Homebrew Channel manifest is still built and attached as a release asset, because the shared build produces it.
- **No telemetry.** The release workflow builds with `telemetry: none`: no Sentry DSN or PostHog key is compiled in (the build step checks the binary for both), and no debug files are uploaded to Sentry. Crash records stay in the television's crash log. The generated `telemetry endpoints` row below is read from the binary.
- **No release candidate** was cut before this release.
- **The reporting code inherited from PlxNative was kept, not deleted.** It is compiled in but has no destination, so it sends nothing. `PRIVACY.md` was rewritten for this release to describe the build as shipped (no reporting, every host the app connects to, what the two metadata-provider requests carry); the description of what that code would send in a build given a destination moved to `docs/optional-reporting.md`, which the telemetry crate's payload tests now read instead of `PRIVACY.md`. The in-app privacy policy (Settings → Privacy & data and Legal) is built from the localized `settings.legal.privacy.*` strings. A build with no destination (`ScreenInputs::telemetry_absent`) now shows its own version of it in all 12 languages. That version has no optional-report, identifier or choice section and lists the same connections as `PRIVACY.md`; the full version remains for a build that has a destination. The sign-in screen's report question and *Send report* are not offered without a destination, because a press would send nothing. The translations other than English and French were written for this release, and no native speaker has reviewed them.
- **The documentation screenshots were not re-rendered** (`make screenshots SHOT_CHECK=1`): the target needs the macOS host FFmpeg build, and this release was prepared on a Linux host.
