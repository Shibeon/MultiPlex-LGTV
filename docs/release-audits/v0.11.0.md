# Release audit — v0.11.0

The evidence behind [the v0.11.0 release note](https://github.com/Shibeon/MultiPlex-LGTV/blob/main/docs/release-notes/v0.11.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written by a person before the release ran.

**The first release of MultiPlex, a fork of [PlxNative](https://github.com/GLinnik21/plx-native).** The fork took PlxNative's `main` after its v0.10.0 release audit (`31e6f24b`), up to and including `8e0f66a6` (2026-11-13), plus one Dependabot bump; every later commit is the fork's own (the identity change `21cbaf03` onward). The authored half below was written on 2026-11-15 against the fork's `main` at `e17da430`, by a drafting agent with no television, no Plex account and no package build: it records what the repository and CI say, and nothing in it was measured on a device. The v0.10.0 tag is not in the fork's repository, and no earlier MultiPlex release exists, so the GitHub compare range appended to the release body has no previous tag to start from.

## Known issues at release, with provenance

- **New features unseen on a television** (the wheel on rows, section spacing, the audio modes' in-app decoding, the search person card against a real server): each commit's body (`d91e5e50`, `3ffccd12`, `058f33be`, `7dbb8196`) records host tests, simulator replays and the mock server only. The audio-mode decoding's lip sync, processor load and the fallback to compressed sound were not measured anywhere.
- **Side-by-side with PlxNative:** the app ids differ (`app.multiplex.native` against `com.beb.plxnative`, from `ci/install-identities.json` here and at `31e6f24b`), so the packages install as two apps, and the storage helper's DB8 kind is named after its own service. The persisted DB8 object id, however, is `plxstate.stable` in both (`ci/install-identities.json`, unchanged by the fork, which kept persisted names on purpose in `0f7446f2`), and the upstream design gives each of its own installs a distinct id. Whether webOS DB8 keeps the two installs' records apart was not checked on a set; it is reported as unknown, not as a defect. Separately, every boot removes the pre-rename `/tmp/plxnative-*` runtime files (`plx_base::paths::remove_legacy_runtime_files`, from `0f7446f2`) when their owner uid is the process's own; the stable runtime root is `/tmp` for both apps, and whether webOS gives two Developer Mode native apps different uids is an open question in `docs/two-installs.md` §6 item 4, so with a shared uid MultiPlex would remove a running PlxNative's logs and crash-reader marker.
- **PlxNative 0.10.0's known issues** are inherited unchanged; their provenance is in PlxNative's v0.10.0 audit.

## Deliberately not done

- **No submission to the webosbrew catalogue** and no change to `webosbrew/apps-repo`: the release is published on GitHub only, by the owner's decision. The Homebrew Channel manifest is still built and attached as a release asset, because the shared build produces it.
- **No telemetry.** The release workflow builds with `telemetry: none`: no Sentry DSN or PostHog key is compiled in (the build step checks the binary for both), and no debug files are uploaded to Sentry. Crash records stay in the television's crash log. The generated `telemetry endpoints` row below is read from the binary.
- **No release candidate** was cut before this release.
- **The reporting code inherited from PlxNative was kept, not deleted.** It is compiled in but has no destination, so it sends nothing. `PRIVACY.md` was rewritten for this release to describe the build as shipped (no reporting, every host the app connects to, what the two metadata-provider requests carry); the description of what that code would send in a build given a destination moved to `docs/optional-reporting.md`, which the telemetry crate's payload tests now read instead of `PRIVACY.md`. The in-app privacy policy (Settings → Privacy & data) is built from the localized `settings.legal.privacy.*` strings, not from `PRIVACY.md`, and was not changed: it still contains the optional-reporting paragraphs.
- **The documentation screenshots were not re-rendered** (`make screenshots SHOT_CHECK=1`): the target needs the macOS host FFmpeg build, and this release was prepared on a Linux host.

## Release configuration

| | |
|---|---|
| flavour | `app.multiplex.native` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK as pinned by the repository's NDK action; Rust as pinned in `rust-modules/rust-toolchain.toml` |
| telemetry | `none` — no endpoint compiled in, no Sentry upload, so the run needs neither the `PLX_SENTRY_DSN`/`PLX_POSTHOG_KEY` variables nor the `SENTRY_AUTH_TOKEN` secret |

New relative to PlxNative 0.10.0's package: a different app id and package name, executables named `multiplex` and `multiplex-storage`, no telemetry endpoint, no contact with `huds.plxnative.com`, and two new read-only requests to Plex's metadata service (`metadata.provider.plex.tv`: a season's announced episodes, and people search).
