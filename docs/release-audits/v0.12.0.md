## Known issues at release, with provenance

- **Every change in this release is unseen on a television.** `6f5fff49` and `bec8b7bc` record host tests, simulator replays and the mock server only (their check runs and `tests/fixtures/replay/README.md`).
- **The wheel change reverses v0.11.0.** `d91e5e50` (in v0.11.0) mapped a wheel notch over a horizontally scrolling row to that row; `bec8b7bc` deletes that mapping (`plx_ui::wheel`, every `DrawFrame::pan_zone`), so one notch is one Up/Down key wherever the pointer rests (`app::bridge::wheel_input`, `docs/DESIGN.md`). The note says so under its own heading because a v0.11.0 user's habit changes.
- **Availability is joined on the primary `plex://` guid only** (`docs/watchlist.md`, "Availability in the user's own libraries"; `docs/pms-api.md` 2d): `imdb://`, `tmdb://` and `tvdb://` answer size 0 from `/library/all?guid=`. A title whose library entry lacks the Plex agent's guid therefore reads "to check" or "not available" although a server holds it under another agent; this was not measured against a real library.
- **v0.11.0's known issues** stand unchanged: the side-by-side install with PlxNative and v0.11.0's own features are still unseen on a set, and PlxNative 0.10.0's issues are inherited. Their provenance is in [the v0.11.0 audit](https://github.com/Shibeon/MultiPlex-LGTV/blob/main/docs/release-audits/v0.11.0.md).

## Deliberately not done

- **No submission to the webosbrew catalogue** and no change to `webosbrew/apps-repo`: the release is published on GitHub only, by the owner's decision, as for v0.11.0. The Homebrew Channel manifest is still built and attached as a release asset, because the shared build produces it.
- **No telemetry**, as for v0.11.0: the release workflow builds with `telemetry: none`, and the generated `telemetry endpoints` row below is read from the binary.
- **No release candidate** was cut before this release.
- **The documentation screenshots were not re-rendered** (`make screenshots SHOT_CHECK=1`). The target stages the host FFmpeg as `.dylib` files (`FFMPEG_HOST_STAGED`, `ci/stage-host-ffmpeg.sh`), which only a macOS host provides, and this release was prepared on a Linux host. The README's and `docs/ux-scenario.md`'s figures were read instead: none shows My list or the MultiPlex HUD's Play disc (`player.jpg` is the Classic HUD), and no caption describes the wheel, the section gap or availability, so no caption was found false; the Home and Library figures predate the wider section gap.
- **No version bump in this commit.** `release.yml`'s `prepare` job bumps the four version files when the release is dispatched.
